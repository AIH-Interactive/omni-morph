# 外部 MOD JAR 预览器实施计划

更新：2026-11-07。工作分支：`preview-acceleration-compare`。

## 目标与边界

交付可通过 `java -jar` 启动、接受命令行参数的独立实窗预览器。Java 包名使用 `top.aihmc.omm`，源码位于 `tools/preview/src/main/java/top/aihmc/omm`，由独立 Gradle 工程构建。复用仓库 Gradle Wrapper，不让预览器构建触发生产模组构建或修改其行为。

直接依赖 `tools/preview/libs` 中的 OmniMorph、OpenYSM、SPM JAR，复用原解析、解密、Molang、动画以及 Java/SIMD/GPU 实现。宿主负责配置输入、依赖装载、窗口、场景、输入适配及测量记录，不复制这些算法，不实现 Minecraft 状态机。不启动游戏。

Figura 仅使用 OmniMorph；普通、加密、旧版 YSM 按各 MOD 的实际支持能力加载。版本不支持时记录原异常及能力差异，不使用自写解析器补齐。

## 输入、资源与界面

- Minecraft 根目录、Fabric/Forge 版本目录、共享 libraries 目录、贴图 JAR、模型路径、皮肤路径均通过配置提供。命令行覆盖配置中的同名运行参数；结果记录最终生效配置。
- libraries 默认 `D:/Program Files/AIHMC/.minecraft/libraries`。必要 Minecraft 配置缺失或失效时显示真实配置弹窗；关闭弹窗则退出，不暗中使用其他安装。
- 皮肤默认 `tools/preview/skin.png`（当前绝对路径为 `D:/UserData/Desktop/Project/OMP/OMP_26.1.2/tools/preview/skin.png`）。支持 `auto/alex/steve`：自动优先使用可用模型元数据，无法确定时由配置明确类型，不声称任意 PNG 都能可靠推断。
- 从本机 Minecraft 26.1.2 JAR 提取贴图，保持 `assets/minecraft/...` 目录，记录源及资源哈希。Minecraft JAR、提取资源、本机配置、用户模型不打包上传。用户已授权提交 `libs` 的 MOD JAR。
- 真实可见窗口以超平坦世界为背景，使用提取贴图；该背景只是预览场景，不模拟世界运行。环境绘制与模型绘制指标分别记录。
- Figura 根据 OmniMorph 实际运行后的原版部件显隐状态补绘未隐藏的原版玩家部件，使用对应 Alex/Steve 模型和皮肤，不通过 Lua 文本扫描猜测显隐，不更改用户模型文件。
- 轮盘和模型设置面板直接复用各 MOD 原界面、定义、回调。Minecraft 图形和输入接口由宿主适配；不能用另一套重写界面宣称已复用。
- HUD 保留 FPS、帧耗时、CPU 阶段、GPU 时间、Present、Draw Call、模型数、进程峰值工作集、焦点、请求/实际后端与回退原因。不能独立测量的项为 NA；不能以堆内存替代进程工作集。
- 支持逐帧 CSV、运行配置/依赖快照与分析报告；GPU 异步计时对应原提交帧，环境和模型开销分开，非聚焦帧单独统计。

## 实施阶段与验收

### 阶段1：分析收口、Gradle 工程与可执行 JAR

1. 核对现有字节码证据，记录各 MOD 的解析/模型生命周期、原渲染后端、动画采样、设置与轮盘入口及所需 Minecraft 对象。
2. 核对 UI 实际依赖：目前已确认 SPM/OYSM 的 ModelSettingsScreen 接收 ModelAssembly、AnimatableEntity、Screen，并使用 Minecraft GUI。类可加载不等于能独立绘制；先确定最小适配接口，再实现。需要超出配置传参边界时记录具体调用链并请求范围决定，不自建游戏客户端。
3. 源码迁移到标准 src/main/java，统一包名 top.aihmc.omm，独立 Gradle 构建并写 Main-Class；清除过时构建路径和启动说明。
4. 各 MOD 使用独立 JVM/依赖集合，避免同名类与 Minecraft/LWJGL 版本冲突。JAR 正式启动流程负责读取配置、准备本机依赖及缺配置弹窗；Python 准备脚本只作为迁移期工具，不能作为最终启动前的隐含必需步骤。
5. CLI 定义至少覆盖配置、MOD、模型、加速模式、皮肤与类型、日志输出及有界验证帧数。未知/重复/缺值参数明确失败；help 不要求 Minecraft 环境。

验收：Gradle assemble 成功；java -jar --help 成功；参数错误返回失败；配置路径含空格可用；两个已验证后端从新入口回归通过；缺配置弹窗真实交互验证。最终启动不依赖手工 classpath 拼接。

### 阶段2：通用模型加载、原动画与三个 MOD 后端

1. 从探针提取模型生命周期适配，接入各 MOD 原文件夹/二进制/加密加载入口，保留解析和失败信息。
2. 配置注入时间、查询值、光照、变换和动作参数；复用原动画运行/采样入口，验证变化时间和多骨骼姿态，避免仅凭固定值证明动画。
3. 接通 OmniMorph 的 YSM/Figura 及 Java/SIMD/GPU；接通 SPM/OYSM 的连续窗口 Java/SIMD/GPU。保留各 MOD 能力检测和回退，记录实际执行入口、CodeSource、DLL 来源。
4. 完成纹理、UV、法线、颜色、可见性与透明部分适配以及资源释放。Figura 与非 OMP 组合在启动前明确拒绝。

验收：真实窗口中模型和动画可见；可用模式分别执行并记录；CPU/SIMD 输出对照和 GPU 独立模型绘制证据通过。故意缺失模型/依赖可得到正确失败，空画面不得通过。原能力不支持的组合记录 UNSUPPORTED，不伪装回退成功。

### 阶段3：超平坦场景、皮肤与 Figura 原版部件

1. 在同一真实窗口加入超平坦地面及天空背景，使用原路径 Minecraft 贴图，保留合理深度关系。
2. 接入配置皮肤及 Alex/Steve，按原 MOD 显隐状态补绘原版部件，保留原绑定与骨骼关系。
3. 验证模型绘制时与仅背景时的差异，避免非背景像素统计在加入地面后产生假 PASS。

验收：实窗检查超平坦背景与模型；Alex/Steve 和可见/隐藏原版部件有对应证据；不修改原模型、不启动游戏。

### 阶段4：MOD 原轮盘/设置、HUD 与记录分析

1. 根据阶段1确定的最小接口接入原轮盘/设置界面与回调，验证操作实际改变原模型参数/动作。
2. 加入 HUD、逐帧记录、配置和依赖快照、汇总分析；时间与内存指标使用正确测量来源，环境成本分列。
3. 检查 UI 文本、焦点、窗口关闭与资源回收。原 UI 无法在既定边界运行时按阶段1范围控制处理，不悄悄替换为自制界面。

验收：真实窗口操作原轮盘和设置有效；HUD 与 CSV/汇总一致；无值指标 NA；记录可定位后端/模型/配置/依赖版本。

### 阶段5：四类真实模型抽样、交付文档与最终审核

1. 从本地实际样本中为普通 YSM、加密 YSM、旧版 YSM、Figura 各随机抽一个；记录种子、类别依据、路径与哈希，不以文件名猜测加密/旧版类别。没有样本时明确记录证据缺口，继续可执行工作。
2. 对适用后端/模式完成实窗加载、动画和绘制验证；解析成功不能代替渲染成功。每轮立即追加 Comparison-Results.md，包括失败和修复后的重跑。
3. 更新 README、INTEGRATION、AGENTS、架构对比与根 AGENT_HANDOFF.md，给出可复制的 Gradle/java -jar 命令、配置字段和实际能力矩阵。
4. 检查 diff、格式、打包内容及 Git 忽略项；确认未夹带 Minecraft JAR/资源、本机配置、用户模型、构建缓存或无关改动。提交用户授权的 MOD JAR 并保留来源/许可证信息。

验收：按本计划逐项核对实现和相应证据；全部要求有覆盖后才完成持续目标。游戏实测始终 MANUAL/PENDING，不作为阻塞条件，不以此要求启动游戏。

## 每阶段固定检查点

按阶段顺序推进；同一阶段内允许多轮定位和回归，不积累多个已完成阶段到一次提交。

1. 所有构建/测试在前台 PowerShell 执行，输出通过 `2>&1 | Tee-Object -FilePath build.log`，立即检查 LASTEXITCODE，失败读取日志。
2. 每轮测试立刻更新对比文档。真实 GUI 使用可见 Windows 窗口，禁止 offscreen。
3. 阶段验收完成后更新本计划进度、INTEGRATION 和必要交接记录，检查 git status、git diff、git diff --check，保留用户无关修改。
4. 提交该阶段并推送 preview-acceleration-compare，核对远端提交与本地一致。
5. 推送确认后查询可靠额度接口，再开始下一阶段。剩余≤10%预警；≤2%优先使用用户授权的 banked reset，接口不可用或重置未恢复时安全保存交接，不启动新阶段。不得猜测额度。
6. 若需额度交接，按根 AGENTS 的 Luna 交接规则执行；人工验收待办不作为目标 blocked 的依据。
