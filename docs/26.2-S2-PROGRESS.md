## 已确认原版变化

通过 minecraft-dev-mcp 26.2 mojmap 源码确认：

- MultiBufferSource、OutlineBufferSource、ParticleFeatureRenderer、ModelPartFeatureRenderer 不再是原版现有接口。不可机械重命名或伪造 net.minecraft 下的兼容类。
- RenderType 无 draw(MeshData)；有 prepare() 返回 PreparedRenderType，primitiveTopology() 替换旧 mode；PreparedRenderType.drawFromBuffer 使用 GpuBuffer / IndexType / baseVertex / firstIndex / indexCount。
- FeatureRenderDispatcher 是 prepareFrame -> 各 FeatureRenderer.prepareGroup -> 共享 StagedVertexBuffer.upload -> executeGroup 流程；PreparedFrame 收尾清理。现有 FeatureRendererDispatcherMixin 的 bufferSource 和 renderSolidFeatures 注入点必须迁移。
- 原版 RenderTypeFeatureRenderer 封装 getVertexBuilder(RenderType)、排序、共享 staged buffer 与准备后的材质绘制，可作为保留行为的迁移参考。
- SubmitNodeCollector 仅扩展 OrderedSubmitNodeCollector；CustomGeometryRenderer 保留。提交记录移入各 feature renderer 内部，旧 SubmitNodeStorage.ModelSubmit 等签名需要逐个核查。
- QuadParticleRenderState 通过 layers()/buildLayer() 构建顶点，submitQuadParticleGroup 提交；QuadParticleFeatureRenderer 使用公共 staged buffer。RibbonRenderState 原来的 prepare/render/ParticleGroupRenderer 接口已移除，已迁为 QuadParticleRenderState 子类，通过原版 layers/buildLayer 与 submitQuadParticleGroup 接入；相关 smoke 测试已迁移但尚未运行。
- PictureInPictureRenderer 无参构造，prepare 增加 FeatureRenderDispatcher，renderToTexture 增加 SubmitNodeCollector，原版在正确 output override 下执行 featureRenderDispatcher.renderAllFeatures。三个 OMP PIP 的隔离、透明、深度与状态恢复须保留。
- GpuFormat 与 BlendFunction/BlendFactor 已读；ReloadableTexture.doLoad 继续用 createTexture(... GpuFormat.RGBA8_UNORM ...) 与 writeToTexture。
