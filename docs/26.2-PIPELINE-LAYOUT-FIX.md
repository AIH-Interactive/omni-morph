# 26.2 solid 管线重复 Globals 修复

日期：2026-11-04。分支：26.2 -> origin/26.2。

## 根因与最小修改

26.2原版MATRICES_FOG_SNIPPET已包含GLOBALS_SNIPPET。FIGURA_SOLID_SNIPPET又同时传入两者，构建器直接追加布局，最终Globals出现在布局0与3。原版GlProgram.setupBindGroupLayouts调用BindGroupLayout.ensureCompatible时抛出日志中的重复名称异常，导致必需solid管线预加载失败及资源包恢复流程。

生产修改仅移除冗余GLOBALS_SNIPPET参数，并加说明。保留Globals、DynamicTransforms、Projection、Fog所需绑定，不更改shader、顶点格式、拓扑、材质及深度/混合状态。没有加入去重fallback或修改原版校验。

## RED / GREEN

- RED：新增本地pipelineBindingLayoutSmokeTest加载真实FIGURA_SOLID，调用原版BindGroupLayout.ensureCompatible，精确复现`Duplicate bind name 'Globals' in bind group layout 3`，进程退出1。见26.2-pipeline-layout-red.log。
- GREEN：最小修改后，30条实际注册的生产管线（solid、24个自定义粒子、4个YSM预览、骨骼高亮）及uniform/storage加速派生布局全部通过原版校验；单独检查solid仍保留四个所需uniform。
- 同批gpuShaderCompilationSmokeTest（原版entity五变体GLSL/SPIR-V）、gpuAccelerationSmokeTest、Fabric/NeoForge assemble通过，总计1分31秒。见26.2-pipeline-layout-green-assemble.log。该shader回归范围是entity加速变体，不冒称solid的驱动编译或GPU像素验收。
- 测试通过生产注册表检查实际布局，初始化延迟注册类但不绘制，不创建GPU设备/窗口，不启动游戏。新增任务仅显式本地调用，不接入生产assemble或Actions。
