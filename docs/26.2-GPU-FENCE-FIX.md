# 26.2 GPU 探针与退出回收 fence 提交修复

日期：2026-11-04。分支：26.2 -> origin/26.2。

## 根因与修改

26.2的GlFence捕获当前submit序号。未调用CommandEncoder.submit就对当前批次阻塞等待，原版GlCommandEncoder.awaitSubmit会直接抛出`Cannot wait on a fence for the current submit`。

- 普通/rigid激活探针与storage entity/rigid/model探针：保留原有绘制、读回、像素校验、1秒等待和资源作用域；顺序修正为建立fence -> 原版encoder.submit -> awaitCompletion -> 读回校验。
- 退出回收：先补齐全部待回收批次的fence，再按设备身份各提交一次，最后在原有总预算内等待并释放。避免新fence落入下一未提交批次；日常poll仍使用0超时，不强制提交、不阻塞。
- 包内私有GpuDeviceAdapter增加submit操作，生产实现调用原版API；已有假设备只补齐接口。未修改GL/Vulkan实现、shader、native C++/JNI/ABI、硬件设置、AUTO路由或错误枚举。

初始化运行时异常仍沿用既有SHADER_FAILURE归类；本次解决该日志背后的提交时序错误，不扩大为状态报告重设计。
