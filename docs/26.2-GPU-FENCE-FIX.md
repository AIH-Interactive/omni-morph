# 26.2 GPU 探针与退出回收 fence 提交修复

日期：2026-11-04。分支：26.2 -> origin/26.2。

## 根因与修改

26.2的GlFence捕获当前submit序号。未调用CommandEncoder.submit就对当前批次阻塞等待，原版GlCommandEncoder.awaitSubmit会直接抛出`Cannot wait on a fence for the current submit`。

- 普通/rigid激活探针与storage entity/rigid/model探针：保留原有绘制、读回、像素校验、1秒等待和资源作用域；顺序修正为建立fence -> 原版encoder.submit -> awaitCompletion -> 读回校验。
- 退出回收：先补齐全部待回收批次的fence，再按设备身份各提交一次，最后在原有总预算内等待并释放。避免新fence落入下一未提交批次；日常poll仍使用0超时，不强制提交、不阻塞。
- 包内私有GpuDeviceAdapter增加submit操作，生产实现调用原版API；已有假设备只补齐接口。未修改GL/Vulkan实现、shader、native C++/JNI/ABI、硬件设置、AUTO路由或错误枚举。

初始化运行时异常仍沿用既有SHADER_FAILURE归类；本次解决该日志背后的提交时序错误，不扩大为状态报告重设计。

测试使用生产MinecraftGpuDeviceAdapter与原版GlFence/GlCommandEncoder.awaitSubmit。仅在测试中用Unsafe初始化原版encoder的submit序号/空sync槽，通过命令记录器推进批次；提交后的空sync槽代表已完成的夹具批次，避免任何GL上下文或GPU调用。绘制命令和绿色像素是固定读回夹具，证明调用顺序/控制流/资源所有权，不作为shader计算或真实GPU像素证据。未扩大生产访问权限，未引入依赖。

两个测试搭建错误单独保留，不计作功能RED：26.2-gpu-fence-fixture-texture-failed.log（缺少String标签texture重载）及26.2-gpu-fence-fixture-bootstrap-failed.log（未设置既有figura.test.directory）。均仅修正测试宿主。

本地最终命令（JDK25，前台Tee-Object完整日志，立即检查退出码）：

```powershell
.\gradlew.bat :common:nativeGpuFenceSmokeTest :common:gpuAccelerationSmokeTest :common:nativeStorageBindingSmokeTest :common:gpuSubmissionSmokeTest :fabric:assemble :neoforge:assemble --no-daemon --console=plain
```

新增nativeGpuFenceSmokeTest仅显式本地调用，不接入Actions或生产assemble。生产行为检查只覆盖实际执行的范围。
