# P4.5：客户端性能数据 HTTP 服务计划

状态：HTTP服务和配套Python/CSV工具已实现并通过P4.5必需自动验收，正在执行阶段提交/推送检查点。实际字段与范围见[HTTP契约](performance-http.md)。执行顺序为P4 → P4.5 → P5；下表仍是候选指标，不表示全部已实现，未观测字段明确返回null及状态。

## 已确认机制

- 服务内置于 OMM 客户端，适用于所有模型和装饰；不修改后端、数据库或同步协议，不依赖 PSF、参考引擎或 application key。
- Debug 模式开启时启动，关闭时停止；端口在“设置 → 性能”中配置。默认仅监听本机回环地址，具体默认端口在实施时确定。
- **一次 HTTP 请求，依次获取一次最新数据，返回一份 JSON。** 请求按顺序排入客户端安全线程取数，HTTP 工作线程等待该次结果并序列化返回。
- 取数发生在处理该请求时；返回采集时间、请求序号、客户端帧号及指标所对应的帧号。模型切换或重载后使用当次最新身份，不复用上一请求的模型快照。
- 不主动推送，不建立持续连接，不启动后台定时采样，不因一次请求而循环采集多帧。已有运行时计数可读取最新完成帧；需要新增计时的候选项须明确单次取样边界，不能把历史值标成当前帧实测。
- P95/P99、平均值、趋势及前后差分，由调用方连续请求后计算；服务首版不维护历史采样库，也不自动调用或重跑模型脚本来生成测量值。
- JSON 同时提供当前选中模型、实际生效模型/实例、所需指标与参考信息。未知或不可获取的值返回 `null` 并标明原因，不用 `0` 代替缺失数据。

## 候选指标表

“可复用”指已有状态或计数可作为候选数据源，实施时仍须核对其刷新时机与统计范围。“需计时”指须增加相应观测点；不因此授权持续采样或完整性能分析器。

### 模型与执行上下文

| 候选数据 | 用途 | 范围与候选来源 | 采集说明 |
| --- | --- | --- | --- |
| 当前选中模型 ID、名称、格式 | 确认本次观察对象 | 衣柜/预览当前选择 | 可复用选择状态；与实际穿戴对象分开 |
| 实际生效 Avatar / 模型 ID | 避免分析到预览或旧模型 | 当前玩家/实体 Avatar | 可复用；包含加载代次，重载后可区分 |
| 生效装饰实例及父子关系 | 定位整套配装中的高开销项 | Outfit 实例与挂载上下文 | 返回实例 ID、资源 ID、启用/可见状态与父实例 |
| 加载状态与最近错误 | 区分加载失败、脚本停止、没有模型 | Avatar / 加载器状态 | 返回阶段与错误标识，不导出凭证或密钥 |
| 当前动作、动画、循环及时间 | 重现偶发开销所在阶段 | 动画与转换后运行时已有状态 | 按适配器能力返回，不假定所有格式都有同名字段 |
| 视角、渲染上下文及暂停状态 | 解释第一/第三人称差异 | 客户端当次渲染上下文 | 可复用；明确取数时处于哪个上下文 |
| 活跃实例、骨骼、网格、纹理数量 | 观察模型复杂度与资源规模 | 已加载模型和资源索引 | 区分资源数量与本帧实际提交数量 |

### Lua 与预算

| 候选指标 | 单位 | 用途 | 采集说明 |
| --- | --- | --- | --- |
| 渲染指令实际消耗 | instructions / frame | 找到超预算和偶发峰值 | 复用 Avatar 指令计数；标明对应完成帧及 pre/post 范围 |
| tick / world tick 指令消耗 | instructions / tick | 区分逻辑与渲染开销 | 读取各自计数，不与 render 混加 |
| 初始化指令消耗 | instructions / load | 分析加载和重载成本 | 属于最近一次加载数据，明确非当前帧值 |
| 配置的基础上限与硬上限 | instructions | 判断正常起点和可增长空间 | 复用性能设置，默认分别为 8192 / 32768 |
| 当次有效额度、剩余额度 | instructions | 解释低信任或共享额度限制 | 复用实际权限与共享账本，不能仅返回设置值 |
| 当次窗口及增长次数 | instructions、count | 判断是否仅偶发触发扩容 | 需在通用 VM 窗口记录最小观测值，不重置计费 |
| 配装总消耗与各实例消耗 | instructions / frame | 定位某个装饰，同时核对总额 | 沿用现有共享账本，避免重复计算父模型与回调 |
| 粒子/动画回调次数及剩余额度 | count / frame 或 tick | 判断回调过密或次数耗尽 | 复用已有回调额度与错误标识 |
| 最近超限的通道、实例及错误 | 标识、instructions | 定位硬上限停止的位置 | 若只存在最近错误，明确记录时间，不当作本次新错误 |

### 渲染、动画与特效

| 候选指标 | 单位 | 用途 | 采集说明 |
| --- | --- | --- | --- |
| 最新客户端帧耗时与 FPS | ms、frames/s | 观察整体卡顿 | 优先复用引擎现有值，并提供该值的统计窗口说明 |
| 当前模型 Lua 渲染阶段耗时 | ms | 区分指令多和原生调用耗时 | 需计时；明确 wall time，不冒充 GPU 时间 |
| 模型动画采样、骨骼更新耗时 | ms | 定位骨骼/动画热点 | 候选观测点，须区分原生 Figura、YSM 与装饰适配器 |
| 模型几何准备/提交耗时 | ms | 定位网格与蒙皮提交成本 | 需计时；覆盖范围随渲染路径标明 |
| 实际提交面、顶点、索引数量 | count / frame | 观察复杂度与几何增长 | 复用已有复杂度/顶点预算或提交计数；不以模型总面数代替 |
| Draw / 批次 / 材质层数量 | count / frame | 定位拆批与多层成本 | 仅报告可观测提交路径，不宣称等于整帧 GPU draw call |
| 活跃粒子数、发射器数 | count | 观察特效规模变化 | 原生粒子状态可复用；脚本私有发射器数不能凭空推断 |
| 粒子实际四边形、顶点及层数 | count / frame | 找到批量粒子和多层绘制开销 | 复用原生粒子提交数据；区分 body、拖尾与 layered |
| 拖尾数量、采样点与提交段数 | count | 判断拖尾历史增长 | 原生实现可读取；Lua 私有历史须另有通用观测来源 |
| 动态光源数量与更新次数 | count / frame 或 tick | 判断光源更新压力 | 候选现有光源运行时计数，注明共享上限 |
| 透明/加法层、材质与管线切换 | count / frame | 分析混合与状态切换 | 需核对已有渲染统计；不为遥测改变绘制顺序 |
| Shader 编译/缓存命中/失效 | count、ms | 识别首次加载和重载尖峰 | 候选已有缓存状态；新增计时必须区分编译与普通绘制 |
| GPU 时间 | ms | 区分 CPU 提交与 GPU 瓶颈 | 需验证目标路径和计时支持；首版允许标记 unsupported，不从 FPS 推算 |

### 内存、资源与请求成本

| 候选指标 | 单位 | 用途 | 采集说明 |
| --- | --- | --- | --- |
| JVM 堆已用/已提交/最大值 | bytes | 判断客户端堆压力 | 优先 JVM 现有管理接口，注明这是进程堆而非全机内存 |
| GC 次数及累计耗时 | count、ms | 让调用方计算差分并关联卡顿 | 返回 JVM 累计值及进程启动代次，不伪装成单帧耗时 |
| 模型纹理数量、尺寸与估算字节 | count、pixels、bytes | 定位贴图资源规模 | 标注估算口径，不能将 PNG 文件大小当作显存占用 |
| 自定义纹理/材质/管线缓存项 | count | 观察重复加载与释放情况 | 优先读取现有缓存统计，不持有资源引用延长生命周期 |
| 待完成加载/上传/编译任务数 | count | 识别异步任务堆积 | 仅输出任务状态，不输出认证信息或资源正文 |
| HTTP 排队及取数耗时 | ms / request | 判断遥测自身是否干扰测量 | 本次请求单独计时，不与模型渲染时间混记 |
| 捕获帧号、计数帧号及数据年龄 | frame、ms | 判断某个字段是否足够新 | 每份 JSON 必带；不同步字段按各自时间标记 |

### 参考数据与指标说明

| 参考数据 | 作用 |
| --- | --- |
| 客户端/模组/API 版本、加载器与 Debug 状态 | 让调用方选择适配规则，区分不同版本的指标含义 |
| 当前设置值、实际权限、共享预算与限制来源 | 区分用户设置、信任等级及当前共享剩余额度 |
| 指标名称、单位、类型、作用域和数据源 | 让 Agent 理解字段，不靠字段名猜测 |
| 当前支持的指标与不可用原因 | 区分 unsupported、not_collected、no_model、not_ready |
| 采集时间、最新完成帧、模型加载代次 | 让调用方安全对齐连续请求，模型切换后停止错误累积 |
| 当前动作/视角等复现条件 | 作为后续优化前后对比的条件参考，不要求重跑脚本 |

## P4.5 实施与验收边界

先完成指标来源盘点与 JSON 契约，再实现 Debug 生命周期、可配置端口和按请求顺序取快照。首批指标优先复用已存在的模型状态、Lua 指令/权限/共享账本和资源计数；计时或 GPU 候选只有在来源可验证时接入。这里没有把完整 profiler、历史数据库、持续采样、远程脚本执行或 MCP 实现加入本阶段。

自动验收须真实启动本机 HTTP 服务并请求 JSON，覆盖 Debug 开/关、端口修改与占用、无模型、切换/重载模型、连续请求顺序和捕获时间更新、跨线程取数、字段单位及不可用状态。一次请求只取一份数据，不触发定时器、重复脚本执行或隐藏的循环采样；关闭 Debug 后释放监听端口和工作线程。回归模型渲染与现有共享预算，并更新 Wiki、构建交付可托管静态 ZIP。

实际界面与游戏内画面未验证时记为 `MANUAL/PENDING`，不作为受阻条件。P4.5 自动验收及提交推送检查点完成后，才开始 P5；最终旧功能回归与 `omm-mcp` 计划书的原有交付顺序保持不变。

## 配套请求与 CSV 记录脚本（已先行交付）

用户已要求先提供独立采集器：`tools/performance_capture.py`，使用 Python 标准库。每次请求获取一份 JSON，多次采集由调用方显式设置次数/间隔并顺序执行。模型选择、生效模型 ID 或加载代次变化时另起 CSV，切回旧模型也不追加旧文件。文件名固定为 **模型名-类型-时间戳.csv**，模型名/类型读取快照元数据，时间戳为采集端 UTC。

CSV 每次成功请求只写一行，指标展开为列，并保留请求/采集时间、帧号、模型/实例、单位、缺失状态与完整 JSON；缺失值不转成0。地址、CSV路径模板、间隔、超时及次数统一由 JSON 配置文件设置，间隔单位为毫秒。工具已通过8项HTTP/CSV测试，包含选择代次变化时的分段；P4.5还实际运行内置HTTP服务、原生Avatar采集器和Python脚本，验证3次请求写入3个模型分段CSV。详见[采集工具说明](performance-capture.md)。OMM dev的AGENTS方法与实际JSON契约已同步；游戏视觉仍MANUAL/PENDING。
