## 修复与验证

- 修正26.2普通/rigid及storage entity/rigid/model探针的同步顺序：建立fence后调用原版encoder.submit，再等待并读回；保留像素校验、超时和资源作用域。

- 五种探针的提交/读回与资源清理、已有和新fence、同/不同设备回收、仅一次释放、空队列不提交均通过。GPU契约、native storage binding、GPU submission及双平台assemble同批GREEN，1分11秒。
- 实际GL命令/像素由记录器提供固定夹具；原版fence检查使用实际Minecraft代码，但不创建GL上下文或GPU设备。因此这些结果证明调用顺序、控制流及资源所有权，不冒充真实驱动/像素通过。
