按用户决定保留 Figura 法线矩阵共享。核对暂存区和工作区，第一轮渲染源码改动仅涉及 ImmediateFiguraRenderer.java，YSM 已处于基线，无本轮 YSM 补丁需撤销。YSM 的 P10 只有第一窗口越过预设阈值，记为待复核。Figura 单层两轮均测得 FPS 上升，A/B 使用不同会话，尚无法归因于法线矩阵共享。Figura 双层主测标为待补模型，本轮收录已完成的结果。

组合①比较 Figura 同次提交内共享主副材质的蒙皮法线矩阵，并覆盖 YSM 回归。Fabric 基线 A 与候选 B 已通过 JDK 25.0.2 打包，归档于 `build/experiment-01/A` 和 `build/experiment-01/B`。

「4D绯夜红伶」常规世界渲染路径已核对。其 34 张模型贴图均为 texture0.png 至 texture33.png，BlockbenchParser2 将它们归入普通纹理，未形成默认副层所需的 _e 纹理。脚本对材质表指定的网格调用 setShaderMaterial，着色器内部的多纹理采样仍位于单次材质提交，ImmediateFiguraRenderer 在该分支清空副层。其余网格未发现脚本设置主副层覆盖的调用。该资产可用于加权单层对照，组合①双层主场景继续待选。

已只读检查指定模型目录内六份 Figura ZIP 的八个 bbmodel，元素中均未发现非空 vertex_weights。当前主场景仍需确认有加权蒙皮且主副材质均生效的资产。

补查项目 common 目录中的 bbmodel，未找到带非空 vertex_weights 的现成模型。refs 在当前工作区为符号链接，未将该链接目标的内容计入本次资产覆盖范围。

后续已解析 refs 符号链接，并补查目标目录中散装 bbmodel，未发现可用的非空 vertex_weights。指定客户端模型目录也未发现新增资产。

A/B Fabric JAR 的 model/ysm 包均包含 167 个 class，条目集合及各 class 字节完全一致。ImmediateFiguraRenderer.class 在两版中有差异。此项记录构建差异，YSM 模拟计时及整包回归仍待执行。

指定目录内的 22 份 YSM 均为 YSGP 封装，文件头核对为 21 份带 BOM 的 YSGP 和 1 份旧版 YSGP。下一步使用项目既有解码路径在计时区间外准备几何，然后复用同一份模型数据模拟提交。此次文件头检查未计入样本。

## 实机 HTTP 采集

### Figura 模型筛查与已知问题

- 其余七份 CS ZIP 均无 `_e` 副层贴图，包内 Lua 未找到主副纹理或渲染类型覆盖的调用，且均含 `setShaderMaterial`。按现有源码，普通贴图网格缺少默认副层，自定义着色材质网格则清空副层。本次静态筛查未找到可用于双层主测的 CS 模型。
- 以顶点权重条目数排序，第二为「4D云归鹤梦-霜吟」（`cs_skin_s9Crane.zip`，178 个有权重骨骼、67,957 条权重）。可用作加权单层对照，实际加载待确认。
- 已知问题（用户实机报告）：「4D绯夜红伶」在衣柜选中后立即显示 `LIBRARY_UNAVABLE`。该场景无有效 FPS 样本，原因未排查，本组合不扩展至修复。
