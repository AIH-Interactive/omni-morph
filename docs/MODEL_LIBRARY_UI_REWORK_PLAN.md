# OmniMorph 模型库界面改造计划

版本：`1.0.0-alpha.2`。建立日期：2026-10-18。

本文单独记录本轮上传修复和界面改造。上一轮 M0～M7 的实现及验收仍见 [原实施计划](MODEL_LIBRARY_IMPLEMENTATION_PLAN.md)，不重新开启已完成阶段。下文区分已交付结果、工作区进行中的代码和待完成验收。

## 1. 用户要求与范围

1. 修复模型库上传异常，包括本次截图中的上传前校验失败。
2. 所有涉及页面按参考图一比一复刻排版，优先使用 Figura 控件。
3. Figura 没有的控件类型自行构造、绘制，并补齐对应交互逻辑及状态。
4. 自绘控件必须契合 Figura：沿用现有字体、深色底、边框、青色强调、悬停反馈、禁用效果和交互习惯。
5. 贴图型控件先绘制各状态 SVG，再通过仓库脚本转换为 PNG；提交 SVG、转换脚本和实际使用的 PNG。
6. 衣柜所有展示/隐藏入口统一放到本次图二所示位置，即模型预览下方、与上传/重新加载/删除相同的操作栏，不继续放在右侧信息栏。
7. 先完成本计划书的检查、单独提交和推送，再按计划继续。每个检查点编译、测试、更新记录、检查差异、提交、推送并确认成功。
8. 用户后续明确：实际游戏内验收交由人工。实际窗口排版、交互、缩放、中文显示和真实上传复验标记 `MANUAL/PENDING`，代理交付验收清单，不自行操作游戏验收，不以此阻塞开发检查点。不能将这些项目写成自动验证通过。

本轮只调整现有模型库及相关衣柜页面和上传故障所必需的代码。保持现有服务端接口、权限、分页和资源安全预算；不增加参考图中尚未授权的模型编辑器、批量审批、操作日志页面、评分、关注、付费或认证平台。不进行范围外重构，不升级版本。

## 3. 控件要求

| 类型 | 实现方式与逻辑 | 必须覆盖的状态 |
| --- | --- | --- |
| 导航、普通按钮、搜索、滚动、预览 | 优先复用 Figura；导航还原五个现有子页及权限可见性 | 未选中、选中、悬停、焦点、禁用 |
| 模型选择/拖放区与封面区 | 在现有 Figura 容器和按钮上自绘组合区域；选择与拖入走同一准备流程 | 未选择、准备中、准备成功、失败、禁用、封面回退 |
| 公开性/需授权单选组 | 自绘单选标记并复用 Figura 事件机制；互斥选择，读取真实草稿值 | 未选中、选中、悬停、焦点、禁用 |
| 多行简介 | 自绘 Figura 风格外观；复用可靠的底层文本编辑、中文输入、选择和滚动机制 | 空、编辑中、焦点、禁用、超限反馈 |
| 标签输入与标签展示 | 还原参考图的标签信息层级；绑定现有标签增删及提交规则 | 空、已有标签、编辑、移除、超限、禁用 |
| 管理与授权表格 | 自绘表头、列、选中行和现有单条操作入口；保留滚动、UUID 确认和权限检查 | 空、加载、正常、选中、请求中、失败、禁用 |
| 管理员登录 | 紧凑居中弹窗，左侧身份区域、右侧输入及底部操作 | 输入、记住可用/不可用、提交、失败、冷却、关闭 |
| 衣柜展示/隐藏和申诉图标 | 分状态 SVG → 脚本 → PNG，使用 Figura 图标按钮及提示 | 隐藏、展示、普通、悬停、禁用、屏蔽不可开启 |

贴图及绘制要求：透明背景、清晰像素边缘、正确 UV 和状态索引；禁止把悬停/禁用帧画反。不会用纯装饰控件假装已有功能。密码保留现有遮蔽、禁止复制和敏感内容朗读的约束。

## 4. 各页面改造内容

### 4.1 我的模型、我的收藏、模型库

- 共用顶部五个子页入口；管理入口遵守现有管理员可见性，加载中的入口不允许触发无效操作。
- 左侧搜索/筛选和卡片网格，右侧独立预览及当前页面对应操作，底部为分页。
- 卡片保留模型类型、名称、作者、多作者提示、收藏、举报和现有统计；处理长文本、缺图与选中状态。
- 我的模型显示本人可执行的编辑元数据/公开性等既有操作；收藏页和公共库显示各自的收藏、启用等操作。
- 授权管理入口只对需要授权且具有管理权限的模型出现。

### 4.2 上传表单

- 顶部同套子页导航；左侧为上传区与封面、名称、只读上传者、只读源作者、分类、标签、公开性、需授权和简介；右侧为隔离预览和底部操作。
- 源选择和自定义封面在表单上方成组显示，避免封面覆盖预览或底部提示。
- 公开性和需授权采用互斥的明确选项，替换仅靠文字下划线表达开关的方式。
- 保留准备阶段、进度、取消、重试和错误提示；失败指出具体校验字段。不得增加静默截断或放宽后端预算。
- 授权默认值继续来自实际 YSM/Figura 源元数据；用户显式修改后，异步准备不得覆盖。
- 上传者只读，来源于服务器认证身份；源作者只读；本地草稿预览不装备、不广播。

### 4.3 模型管理

- 顶部子页、搜索/筛选、表头、模型行、分页和操作位置参照参考图。
- 表格呈现模型、作者、上传者、状态、下载等现有数据和当前可执行操作；原接口未提供的数据不编造。
- 保留单模型授权管理、屏蔽、解除屏蔽、删除及现有二次确认和版本冲突处理；不增加批量审核。
- 举报、申诉和当前衣柜管理作为现有管理入口保留，并使用一致的版式。

### 4.4 授权管理

- 采用参考图的模型上下文侧栏、玩家搜索、UUID 列表和操作区结构。
- 搜索结果先展示已认证 UUID，再独立确认授权；撤销保留独立确认和既有 CAS/幂等语义。
- 不显示尚未实现的功能导航；私有模型的现有授权记录保留规则不变。

### 4.5 管理员登录及相关页面

- 登录还原参考图的居中、紧凑、左右分区和底部操作布局；窗口缩放后不遮挡输入和反馈。
- 关闭/切换后清空密码，保持记住登录的现有凭据保护、冷却及当前账号绑定。
- 举报、申诉、衣柜管理、文件选择和展示设置统一使用相同间距、分区、表单/列表风格及明确返回路径。

### 4.6 衣柜操作栏

- 将展示/隐藏从右侧信息栏移到预览下方操作栏，以实际状态图标表达当前可见性；申诉入口同栏。
- 状态按当前启用资源查询并绑定其资源版本及装备版本；更新请求复用现有接口，不更改上传/重新加载/删除的语义。
- 上传准备、请求中、无可用资源、后端不支持或模型被屏蔽时正确禁用；失败后重新读取权威状态。
- 衣柜上传默认展示；模型库私有装备的展示意图默认关闭，两个已有规则不能混用。
- 屏蔽仍强制仅本人可见，任何控件和旧状态都不能重新开启对外展示。
