# Minecraft 26.2 与 Vulkan：主源研究记录

查证日期：2026-11-03（Asia/Seoul）。本文仅记录研究事实和实施建议，不代表已经编译或完成客户端验证。

## 结论与范围

26.2 正式版已经加入原版实验 Vulkan 后端。适配目标应是在原版 OpenGL、Vulkan 两种后端下保持 OMP 现有功能，而非另写 Vulkan 渲染器。官方设置允许选择后端并可能自动回退，因此启动成功本身不能证明正在使用 Vulkan；验证时必须记录 F3 实际后端。[Minecraft 26.2 发布说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-2)

VulkanMod 是另一个独立模组，项目说明其自行提供 Vulkan 渲染引擎。本次原版 Vulkan 适配不应自动引入 VulkanMod 依赖，也不能把 VulkanMod 的结果当作原版后端结果。[VulkanMod 项目说明](https://github.com/xCollateral/VulkanMod)

## 对实施有直接影响的迁移点

Fabric 明确要求依赖原始 OpenGL 调用的模组迁移至 Blaze3D，否则无法支持新后端；这应覆盖绘制、纹理上传和读取、帧缓冲以及着色器路径，不能只改依赖版本。[Fabric 渲染基础文档](https://docs.fabricmc.net/develop/rendering/basic-concepts)

26.2 还将当前 Screen 的访问移入 `Minecraft.gui`。因此 GUI 入口迁移与渲染后端迁移应一并纳入调用点清单。[Fabric 26.2 官方迁移说明](https://fabricmc.net/2026/06/15/262.html)

Fabric 官方迁移文章链接的 NeoForged porting primer 提示以下 API 变化：顶点格式构造调整；`VertexFormat.Mode` 与索引类型迁移；管线采用 `BindGroupLayout`；RenderPass 描述和附件调整；GPU 缓冲映射、纹理上传及格式类型变化；Font 文本改为准备和提交路径。这份文档是迁移线索，精确签名应以 minecraft-dev-mcp 缓存的 26.2 源码为准。[26.2 Porting Primer](https://github.com/ChampionAsh5357/neoforged-github/blob/port%2F26.2/primers/26.2/index.md)

## 必须单独核实的 NeoForge 启动问题

NeoForge 官方问题 #3230 记录：启用 Vulkan 后，早期加载窗口导致 GLFW 启动错误；评论给出的临时措施是将 `fml.toml` 的 `earlyWindowControl` 设为 `false`。问题于 2026-09-27 关闭，发布机器人明确标记修复版本为 `26.3.0.26-beta`。该证据没有证明 26.2 已回移修复。实施阶段应先在 26.2 候选加载器的干净客户端验证，再验证 OMP；不能直接将启动失败归因于 OMP，也不应未经调查修改 OMP 产品逻辑规避加载器问题。[NeoForge #3230](https://github.com/neoforged/NeoForge/issues/3230)

## 当前证据缺口

- 未验证本项目现有 Architectury 插件与 Loom / Gradle 候选组合；不得直接假设替换插件即可工作。
- 未锁定 Iris、ImmediatelyFast、LambDynamicLights、Mod Menu、GeckoLib、MCLib 的 26.2 兼容坐标；实施前应逐个检查作者官方发布元数据、加载器和后端支持。上游存在 26.2 文件也不自动代表其支持 Vulkan。
- 未在真实客户端执行 OpenGL / Vulkan 回归，也未验证硬件和驱动能力；上述研究不能记为游戏功能 PASS。
- 本文件不证明 minecraft-dev-mcp 缓存状态；缓存路径、版本和索引结果由统一计划书记录。

建议实施顺序：先锁定现有工具链兼容组合，再完成 API / Mixin 迁移和 Blaze3D 后端中立化，最后对两个加载器、两种实际后端运行同一组现有功能用例。候选依赖需经过解析、构建及真实客户端验证后才能成为最终锁定值。
